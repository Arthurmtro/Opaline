# Opaline

macOS SwiftUI app + `OpalineKit` package. See README for what each target writes, docs/THEME_FORMAT.md for the format.

## Commands

- `swift test`: engine tests. Run after any change in `Sources/OpalineKit`.
- `Scripts/run.sh`: regenerate the Xcode project, build, relaunch. It refuses when a snapshot changed in the last 2 minutes, so it never kills an apply in progress.
- The `.xcodeproj` is generated by XcodeGen from `project.yml`; never edit it.

## Rules

- A target only writes through `changes(for:in:)`; the engine snapshots every original before writing.
- Edit user configs in place: `JSONCEditor` for JSONC, `ManagedBlock` for line-based configs, `FirefoxPrefs` for `prefs.js`.
- Targets whose app rewrites its files on quit (Zen) set `quitsApp`; the engine closes and reopens them.
- The theme file format is public: a new role goes in `Palette` (with a derived default in `ThemeDefaults`), its `fields` table,
  the schema, docs/THEME_FORMAT.md, the built-in themes and the editor, together.
- Built-in themes live in `themes/defaults` (exchange format, valid against `schema/theme.schema.json`); `themes/custom` is gitignored
  and bundled too. The app reads both from the bundle; user files with the same id override them.
- No personal or company data in the repo: themes, names and paths stay generic.
- Verify UI changes with a capture of the running app.

## Gotchas

- WKWebView rendering (wallpaper) needs the app run loop: it hangs in `swift test`. Hidden windows get no animation frames,
  so the renderer waits a fixed delay, and its offscreen window overrides `constrainFrameRect` to keep large sizes.
- Claude Code ignores custom theme overrides for markdown inline code and links (resolved by built-in theme name).
- Zen keeps 20 % of the window material under its theme at max opacity; the target turns vibrancy off.
